# 分批检查协议（超长篇 · 任意小说）

> **定位**：把「全书 8 维」从"一次读进上下文"改为**分批扫描 → 中间检查点 → 汇总**的可重复协议。
> **用这个**：书稿超过约 30 万字、或单次检查读不完时；也可用于任何多章改稿后的复扫。
> **不是那个**：章级检查（章级仍走 `novel-check` 单章流程）；也不是"跳过检查直接汇总"。

被 `novel-check`（阶段 1·2）与 `.cursor/skills/novel-plan/reference/universal-gates.md` §2 引用。

---

## 1. 为什么要分批

`novel-check` 的 8 维度要求"读目标章节 + 全部相关设定"。书稿变长后：

- 一次性读入会**挤掉设定文档**（模型先丢设定，再丢前文），维度 3/5/7 最容易失真；
- 一次跑完无中间产物，**中断即全废**，也无法复扫单项；
- 汇总时**无法区分**"这章真的没问题"和"这章没读到"。

分批协议解决这三点：每批都有落盘的检查点，汇总只读检查点。

---

## 2. 三步协议

### 第一步 · 分批（Plan）

| 决策 | 口径 |
|---|---|
| **批大小** | 按**章**切批，每批 3–5 章（短篇可整书一批；超 60 万字取 3 章） |
| **批数** | `批数 = ceil(总章数 / 每批章数)`；批数 > 12 时先做**抽样批**（开篇窗 / 中点 / 高潮区各 1 批）再决定是否全量 |
| **共享设定** | 世界观 / 人物卡 / 主线剧情 / 伏笔板 / 通用约束 / 节奏窗**每批都要读**（它们是跨批约束，不能"上一批读过了"） |
| **批顺序** | 按章号升序；**伏笔与量纲必须升序**（跨章状态依赖前一状态） |
| **范围闸** | 遵守 `.cursor/skills/novel-plan/reference/universal-gates.md` §2：上一份同范围主报告仍有效且未跨章大改 → 只开专项，不做全量重扫 |

### 第二步 · 扫描（Scan）× N 批

每批独立执行 8 维（或本批需要的专项），**每批产出一个检查点文件**：

```
.cursorGrowth/check/第NN-MM章_检查点.md
```

检查点必须包含（缺一即视为该批未完成）：

```markdown
# 检查点 · 第 NN–MM 章 · YYYY-MM-DD

## 批次元信息
- 批号：k / 总批数
- 章范围：第 NN–MM 章
- 本批已读设定：世界观 / 人物卡 / 主线剧情 / 伏笔板 / 通用约束 / 节奏窗（逐项勾选）
- 本批字数：

## 8 维度结论（本批）
| # | 维度 | 结论 | 证据（章·节） |
|---|------|------|--------------|

## 🔴 必须改（本批）
## 🟡 建议改（本批）

## 跨批状态（交给下一批）
- **伏笔状态**：本批新埋 fs-…；本批回收 fs-…
- **量纲真值**：本批确认/修正的常量（年龄/编号/价格/距离…）
- **时间线锚点**：本批末尾的故事内时间
- **待下一批核对的悬置项**：
```

> **跨批状态**是分批协议的核心：它让"第 3 批"不必重读第 1–2 批原文，也能接住伏笔与量纲。

### 第三步 · 汇总（Aggregate）

汇总**只读检查点**（不重读正文），产出主报告：

```
.cursorGrowth/check/全书_ncheck.md
```

主报告必须：

1. 列出**全部批号与覆盖章范围**，并显式声明**未覆盖范围**（若有）；
2. 跨批去重：同一问题在多批出现 → 合并为一条，标注章范围；
3. 伏笔总账：把各批「跨批状态」的伏笔增量累加成一张总表，与 `主题/伏笔板.md` 对账（不一致以伏笔板为准，并标 🔴）；
4. 量纲总账：各批确认的常量取**唯一真值**，冲突则列 🔴 并给"先定真值再改一侧"的处置；
5. 三档决策（✅ / 🟡 / 🔴）与下一步（`/nfix` 或复扫）；
6. `Sprint 闭合后`才整体迁 `archive/`。

---

## 3. 复扫与增量

| 场景 | 做法 |
|---|---|
| 修完 🔴 后复扫 | **只重跑受影响批次**；跨批状态沿用未变批次 |
| 中途新埋伏笔 | 只更新对应批检查点的「跨批状态」，并同步 `主题/伏笔板.md` |
| 结构大改 | 全量重扫（旧批检查点作废，移入 `archive/`） |
| 专项（时间漏网 / 量纲 / 对白 / 外发硬伤） | 用专项跑全部批次的对应维度，不重跑其余 7 维 |

---

## 4. 附：机械先行（强烈建议）

分批前先跑写作侧机械校验，把"排版级"问题先清掉，避免它们污染 8 维判断：

```bash
python3 .cursor/tools/check_manuscript.py            # 密度 / 长句 / `##` 标题 / 元叙事 / 标点 / 敏感词
```

机械项 🔴 清零后再进本协议；机械项结论**不进** 8 维评分（文字层不在 8 维内，见 `novel-check`）。
